A Skill Card

frontend-slides/静态幻灯片生成

把一篇稿子打磨成可放映的纯 HTML 幻灯片——单文件、零依赖，放映与打印同源。

分类 · presentation 触发 · /frontend-slides 风格 · 静态 HTML · 印刷感

01它是什么

frontend-slides 是一个把稿子变成可放映 HTML 幻灯片的 skill。它接 outline、章节、要点列，吐出一份单文件、零外部依赖、可在浏览器全屏放映的 .html。

它给稿子套上幻灯节奏：一屏一题，行数封顶，引用必有出处。多余的论述被强制外溢到下一屏，或下沉到演讲者备注。

它交付的是一份印刷品——浏览器里放、投影仪投、A4 黑白印，是同一份字。

它牺牲动画、图表、视频，换来的是：每一页都能讲、都能印、都能存档。

02怎么触发

在对话框直接输入：

/frontend-slides 把上周三的读书会记录整理成一组幻灯片

触发参数里贴上原始材料。可以是会议纪要、章节草稿、bullet 大纲、一段讲稿——甚至是一份录音转写。

agent 接到后会先做内容清洗——把口语化的连篇段落拆成一屏一题的短句——再排版，不会原样照搬。如果稿件太散，它会反问"讲给谁听、时长多少"。

03核心机制

frontend-slides 同时守住两件事，少一件都不算完：

  1. 一屏一题——每张 slide 只能承载一个核心命题。多余的文字会被强制外溢到下一屏，或下沉到演讲者备注。这是它的根本节奏：长稿必须被切碎，不能任由作者堆砌。
  2. 放映与打印同源——同一份 HTML 在浏览器全屏、投影仪投射、A4 黑白打印三个场景下，版式不塌。靠的是相对单位、同一套 token、避开依赖具体屏幕宽度的写法。

切屏靠 scroll-snap 滚动吸附，不用键盘翻页器也能"刷到下一屏"；同时键盘 ↓ / Space / PageDown 同效。

不强制要键盘控制，但保留——投影现场的网络设备不响应 Space 时，你还能滚轮过去救场。

04输入与产出

能吃下的输入：

类型 处理方式
会议纪要 / 录音转写 长流水，先抽论点再切屏。
章节草稿（Markdown / Word） 按段落切屏，标题直接做页眉。
纯 bullet 大纲 一条一屏。
已发表的讲稿 / 文章 按论点切屏，引文段直接做页脚。

产出文件：

<name>-slides.html主件——放映、打印、发链接，都用它。
<name>-notes.md 演讲者备注。每页一段，详于页面正文。
<name>-slides.pdf 可选。需要时走浏览器打印，或 wkhtmltopdf。

05设计基底

frontend-slides 的视觉选择有六项明确决定，slide 内部全部遵循：

  • 衬线大标——Source Serif Pro / 宋体，64–96px，远观可读
  • 等宽小标——SF Mono / Consolas，11–13px，编号、页码、文件名
  • 墨青主色——#0f5e54，仅用于强调与编号小点
  • 白底深墨——白底 + #14181c 正文，避开渐变与暗色背景
  • 视口吸附——每屏 100vh，scroll-snap 切屏
  • 页码显形——右下角小号"03 / 12"格式

六项不靠 CSS 框架实现，全部内联在单文件 HTML 里。打印走浏览器原生 @media print，白底黑字直出。

06幻灯节奏

frontend-slides 写出的每张 slide 必须满足五条规矩：

  1. 一题——一张 slide 只能主张一件事。出现第二件事，就拆。
  2. 一行——核心命题用一行字说清，超过两行就拆或下沉到备注。
  3. 一数——给每张 slide 一个数（编号、百分比、年份），方便回指"前面第几页"。
  4. 一引——出现的引用、数据、案例，必有出处链接或机构名。
  5. 一停——slide 之间留明显空白或细分隔线，不要链式堆叠。

幻灯是断奏不是连奏。听众每次抬眼都要"重新找到调子"，这是节奏服务的对象。

07一页例子

这是 frontend-slides 写出的某张 slide 的实际 HTML 结构：

<section class="slide">
  <span class="num">03 / 12</span>
  <h1>一屏一题是节奏的根</h1>
  <p>长稿必须被切碎——剩下的文字下沉到备注，<br>不能任由作者堆砌。</p>
  <cite>——内部约定，2026-10</cite>
</section>

配上一段最小 CSS，一屏就成型：

.slide {
  min-height: 100vh;
  scroll-snap-align: start;
  padding: 12vh 8vw;
  display: grid;
  align-content: center;
}
.slide h1 { font: 600 72px/1.1 "Source Serif Pro", serif; }
.slide .num {
  position: fixed; right: 4vw; bottom: 4vh;
  font: 11px/1 "SF Mono", monospace; color: #8a9099;
}

一份完整 deck 通常是 12–30 张这样的 <section class="slide"> 顺序排列，主件不到 30KB。

08适用与不适用

适用：

  • 10–30 分钟的内部分享、读书会、组内汇报、家长会。
  • 把一篇已写完的稿子或章节凝成"讲得动"的形式。
  • 想用最轻的工具做投影片——双击 HTML 即放。
  • 需要把讲稿存档、可分享链接、可打印发出去。

不适用：

  • 需要复杂动画、视频嵌入、交互的场合。
  • 演讲稿本身还没写出来——先把理解沉淀成稿，再来 frontend-slides。
  • 公司强制模板（要 logo、要配色规范）——硬塞企业 VI 会别扭。
  • 超 40 张的马拉松式汇报——节奏会塌，先拆成两场。

09三步开干

  1. 选一份原始材料，贴在 /frontend-slides 后。可以是笔记、章节、大纲，甚至是一段录音链接。
  2. 看 agent 切出的页面大纲——可以合并、拆分、换顺序，它只是初稿，不是定论。
  3. 拿 <name>-slides.html 双击即可放映；浏览器全屏（F11）即投影；Cmd/Ctrl + P 可打印成讲义。

讲完之后 HTML 不要删——它就是这次分享的存档。

改稿时直接说"第三页换成一句口号"，agent 就把那份 HTML 里编号为 03 的 <section> 整张替换掉。
